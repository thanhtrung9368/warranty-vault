# Web i18n — how to translate a screen

Phase 4 of [docs/I18N_PLAN.md](../docs/I18N_PLAN.md). The Go API speaks both
languages (phases 0–1); this is the web client catching up.

**Vietnamese is the ORIGINAL.** Every sentence in this app was written in
Vietnamese first. The job is to *wrap* those literals and *add* an English
column — never to retranslate the Vietnamese.

## Where the language comes from

```
wv_locale cookie  →  User.locale  →  Accept-Language  →  "en"
```

Resolved once per request by `getLocale()` in `src/lib/i18n/server.ts`, and the
same answer drives both the UI and the language of API responses (`apiFetch`
appends `?lang=<locale>`, which is level 1 of the Go server's own chain).

- `src/lib/i18n/locale.ts` — pure primitives (precedence, `Accept-Language`,
  `withLangParam`). No framework imports.
- `src/lib/i18n/request.ts` — server-only cookie/header readers + writers.
- `src/lib/i18n/server.ts` — `getLocale()` / `getI18n()` / `getT()`.
- `src/lib/i18n/client.tsx` — `<I18nProvider>`, `useLocale()`, `useT()`.
- `src/lib/i18n/catalog.ts` — `translate()`.
- `src/lib/i18n/messages/*.ts` — the dictionary, one file per domain.
- `src/lib/i18n/labels.ts` — locale-aware enum labels.

## The three call shapes

**Server Component / page / layout** — resolve once per file:

```tsx
import { getI18n } from '@/lib/i18n/server';

export default async function Page() {
  const { locale, t } = await getI18n();
  return <h1>{t('Thiết bị')}</h1>;
}
```

**Client Component** — the locale arrives through the provider in the root
layout:

```tsx
'use client';
import { useT, useLocale } from '@/lib/i18n/client';

export function Widget() {
  const t = useT();
  const locale = useLocale();      // only when a helper needs it
  return <button aria-label={t('Xoá')}>{t('Lưu')}</button>;
}
```

**Pure module** (`src/lib/*.ts`, no React) — take the locale as a parameter and
translate at the call site or through `translatorFor`:

```ts
import { translate } from '@/lib/i18n/catalog';
import type { Locale } from '@/lib/i18n/locale';

export function describe(x: Thing, locale: Locale): string {
  return translate(locale, 'Còn {days} ngày', { days: x.days, count: x.days });
}
```

`locale` is **required** on these — no default. An optional parameter with a
Vietnamese default would let a missed call site render Vietnamese inside an
English page and report nothing.

## Adding a message

The key IS the Vietnamese sentence. `defineMessages` derives the `vi` column from
the key, so it is never typed twice:

```ts
// src/lib/i18n/messages/devices.ts
export const devices = defineMessages({
  'Thêm thiết bị': 'Add a device',
  'Còn {days} ngày': '{days} days left',
});
```

Then `t('Thêm thiết bị')` / `translate(locale, 'Thêm thiết bị')`.

Rules:

1. **Wrap, don't rewrite.** The Vietnamese literal stays byte-for-byte what it
   was; it just moves inside `t(...)` and becomes a key.
2. **Interpolation is `{name}`**, not `${name}`. A template literal
   `` `Còn ${days} ngày` `` becomes `t('Còn {days} ngày', { days })`. The key is
   the template *with the placeholder*, which is the canonical form of that
   sentence — that is the one place a key legitimately differs from a raw
   literal.
3. **Plurals.** Vietnamese does not inflect; English does. When the sentence
   contains a count, pass `count` alongside it and add the singular English form:

   ```ts
   'Còn {days} ngày': { en: '{days} days left', enOne: '{days} day left' },
   ```
   `translate(locale, key, { days: 1, count: 1 })` → `1 day left`.
   Without `enOne`, English reads "1 days left" — a bug.
4. **Reuse the server's wording.** `api/internal/i18n/catalog.go` already has an
   English sentence for every concept the API returns. When the same sentence
   exists there, copy its English exactly; do not invent a second phrasing. It is
   a map of `"Vietnamese": {vi: …, en: …}`. Example:
   `"Bạn chưa đăng nhập"` → `"You are not signed in"`.
5. **Do NOT translate comments, log lines, `console.error`, test fixtures, CSS
   classes, or the `vi-VN`/`en-US` identifiers.**
6. Every entry must carry a non-empty English string, and the English must not
   contain Vietnamese-only characters (`ă â đ ê ô ơ ư` and the tone-marked
   vowels). `src/lib/__tests__/i18n.test.ts` enforces both — copying the
   Vietnamese through as the "translation" fails the build.
7. A sentence that is identical in both languages needs **no entry at all**:
   `t('Laptop')` returns the key, which is already correct. Adding a redundant
   entry is harmless but pointless.

## Shared vocabulary

`messages/common.ts` holds the app shell (nav, layouts), generic verbs
(Lưu / Huỷ / Xoá / Sửa / Thêm …), the language switcher and the transport
fallbacks from `lib/api/client.ts`.

**Before adding a key to your own file, grep `src/lib/i18n/messages/` for it.**
Two domain files defining the same key with different English is a test failure
(`conflicts` in `messages/index.ts`). Identical duplicates are tolerated but
untidy — prefer reusing.

## Locale-aware helpers

```ts
formatVND(amount, locale)          // 1.200.000 ₫  /  ₫1,200,000
formatNumber(n, locale)            // 1.200.000     /  1,200,000
formatDate(d, locale)              // 07/05/2026    /  05/07/2026
formatDateLong(d, locale)          // Thứ Ba, …     /  Tuesday, …
formatRelativeDay(d, locale)       // hôm qua       /  yesterday
warrantyState(end, locale).label   // Còn 3 ngày    /  3 days left
categoryLabel(code, locale)        // Điện thoại    /  Phone
statusLabel(status, locale)        // Đang dùng     /  In use
warrantyTypeLabel(type, locale)
billingCycleLabel(cycle, locale)
subscriptionStatusLabel(s, locale)
wishlistPriorityLabel(p, locale)
wishlistStatusLabel(s, locale)
labelOf(map, code, locale)         // any code → Vietnamese map
```

The raw label maps stay Vietnamese on purpose — they are the source text, and
`CATEGORY_LABELS` in `lib/types.ts` is parsed by a Go test that lives outside
this change. **Never reshape that object literal.**

## Server actions

- `toFormState(res, { message })` is **async** and resolves the language itself.
  A `message` you pass is treated as a catalog key, so keep passing the
  Vietnamese sentence: `toFormState(res, { message: 'Đã lưu thiết bị' })`.
- Strings a server action returns in its own state object (`{ message: '…' }`)
  must go through `t(...)` — an action can `await getI18n()`.
- Identity + parsing + `revalidatePath` stay in the action; business logic stays
  in Go.

## What NOT to touch

- `api/**`, `ios/**`, `android/**`, `deploy/**`, `openapi.yaml`, root `*.md`.
- The `CATEGORY_LABELS` object literal in `src/lib/types.ts`.
- `docs/` and code comments.
- `next.config.mjs` CSP.
